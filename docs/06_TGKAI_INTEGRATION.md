# Стыковка с tgKAI (animagross)

tgKAI (`lib/tgKAI/social/` в репозитории animagross, pm2-служба `ag-tgkai`) уже публикует в VK, Boosty, Patreon, Telegram, 3DToday (выключен) и Cults3D. YouTube и TikTok там пока нет.

## Разделение ролей
- **AGaiani**: делает клипы (кадры -> видео -> шорт).
- **tgKAI**: раздаёт готовый шорт по площадкам (очередь, повторы, алерты админам, расписание).
- Контракт между ними: файл ролика + заголовок + описание + теги + ссылка на сайт.

## Что добавить в tgKAI (в проекте animagross)
- Площадки `youtube`, `tiktok` в типе `Platform` (в `socialDb.ts`) и адаптеры публикации.
- Типы постов `vt_short` (шорт с Ани) и `vt_stream_announce` (анонс эфира). Пост типа `contest_video` с `videoPath` уже есть, его можно взять за образец.
- Таблица `vt_clips`: путь к mp4, id фигурки, статус (ждёт одобрения / одобрен / опубликован), площадки.
- UTM-метки на каждой ссылке: `?utm_source=yt|tt&utm_campaign=ani`, чтобы видеть реальные переходы на сайт.
- Статистика на `/admin/tgkai` или `/admin/vtuber`.

## Как публиковать
- Сначала официальные API (YouTube Data API, TikTok Content Posting API): нужны OAuth и, как правило, аудит приложения до публичных публикаций. Условия и квоты проверить по актуальной документации.
- Браузерная автоматизация (как у VK и Boosty) быстрее запускается, но чаще ломается и рискует блокировкой аккаунта.
- Старт: публикация приватно/черновиком и **ручное одобрение** каждого шорта, как у промо-роликов.

## Повторное использование из animagross
- Фильтр NSFW: `contentRules.ts` (промо-конвейер уже пропускает откровенные фигурки).
- Монтаж и очередь одобрения: `compose.ts`, таблица `promo_videos`, сервис `ag-animistrator`.
- Выход новой фигурки, конкурс, победитель: события, на которые Ани реагирует (в ТЗ это шина `vt_events`).

## GPU
Видеокарта одна. Промо-режиссёр (Ollama, qwen2.5vl), Real-ESRGAN и рендер Studio не должны работать одновременно: расписание «ночь рендерим, день публикуем» или внешний API для LLM.
